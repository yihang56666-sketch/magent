# Codex 原生子智能体编排 Skill：详细中文 GitHub 发布设计

## 目标

将 `magent` 仓库重新定位并发布为单一、通用的 Codex Skill。GitHub 访问者应能在 README 中快速理解它解决什么问题、怎样安装、如何使用、相比原生子智能体增加了什么，以及它不能保证什么。

## 发布范围

- 将根目录 README 改为中文为主的详细项目说明，保留 `spawn_agent`、Skill 等必要英文术语。
- 保持 `codex-native-subagent-orchestrator/SKILL.md` 精简，不把面向读者的介绍重复塞入运行时上下文。
- 更新 GitHub 仓库首页简介，使其与 README 和当前产品定位一致。
- 将 `github-public-release` 安全快进到 `main`，不强制推送，不重写历史。
- 不提交两份未跟踪的旧 Magent 计划文档。

## README 信息结构

1. 一句话定位与核心价值。
2. 原生子智能体与本 Skill 的职责对比。
3. 适用场景与不应分派的场景。
4. 编排流程：判断、选角、分派、收集、冲突处理、验证。
5. 内置角色、动态临时专家和默认团队规模。
6. 只读约束、共享工作区保护和外部操作边界。
7. 失败、超时、缺失结果及有限恢复策略。
8. 一个端到端使用示例。
9. Windows、macOS/Linux 安装与 Codex 原生子智能体前置条件。
10. 仓库结构、验证命令、限制、常见问题和许可证。

## 准确性边界

- 原生 `spawn_agent` 是执行引擎，本 Skill 是决策、路由、安全、恢复和汇总层。
- Skill 不提升模型本身的智力，也不保证多智能体一定更快或质量一定更高。
- 子智能体只读属于明确指令与工作区审计约束，不声称提供独立的权限沙箱。
- 主智能体始终是唯一写入者、最终验证者和用户交互负责人。
- 默认使用 1–3 个子智能体；只有安全敏感或明显跨领域任务才考虑第 4 个。

## 验证与发布

- 运行 `python -m unittest discover -s tests -v`，要求全部契约测试通过。
- 运行可用的官方 Skill validator；不可用时只记录跳过，不虚构结果。
- 运行 Markdown 链接检查、`git diff --check` 和发布文件扫描。
- 只暂存本次 README、测试或必要元数据修改。
- 先推送 `github-public-release`，再以快进方式更新远程 `main`。
- 更新 GitHub 仓库简介后，读取远程分支提交和仓库元数据确认发布结果。
